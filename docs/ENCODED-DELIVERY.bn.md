# ক্লায়েন্টের হোস্টের জন্য এনকোডেড PHP ডেলিভারি

এই সেটআপ মূল অ্যাপ, ডিজাইন বা ডেটাবেস পরিবর্তন করে না। এটি যাচাই করা Git snapshot থেকে **আলাদা ZIP** বানায়:

| কী | ZIP-এ কীভাবে থাকবে |
|---|---|
| সার্ভারের `.php` ফাইল | একই নাম ও পাথে ionCube-এ এনকোডেড; plain PHP সোর্স নয় |
| CSS, JavaScript, ছবি, ফন্ট, লাইসেন্স নোট ও অ্যাপের রেট ফাইল | হুবহু একই বাইট; ডিজাইন ও ব্রাউজার ফিচার অপরিবর্তিত রাখার জন্য |
| ডেটাবেস, SQL, ডেটাবেসের পাসওয়ার্ড, আপলোড, লগ, `.git` | থাকবে না |

ক্লায়েন্টের হোস্টে ডেটাবেস আলাদাভাবে থাকবে। কানেকশন সেটিংস `ICONIC_DB_HOST`, `ICONIC_DB_NAME`, `ICONIC_DB_USER`, `ICONIC_DB_PASSWORD` ও প্রয়োজনে `ICONIC_DB_PORT` দিয়ে হোস্টে সেট করতে হবে, ZIP-এ নয়। ব্রাউজার যে HTML/CSS/JS ব্যবহার করে, সেটা দেখা বা নিজের ব্রাউজারে বদলানো আটকানো যায় না। PHP এনকোড করার পরও সার্ভারের মালিক ফাইল সরাতে বা প্রতিস্থাপন করতে পারেন। এই প্রক্রিয়ায় কোনো গোপন লক, মেয়াদ বা রিমোট নিয়ন্ত্রণ যোগ হয় না।

## রিলিজ বানানোর আগে

- [হ্যান্ডওভার গাইডের](HANDOVER.bn.md#লাইভ-করার-আগে) রিভিউ শেষ করুন। এই সোর্স এখনো সরাসরি লাইভে দেওয়ার জন্য অনুমোদিত নয়। পুরোনো ব্যক্তিগত ডেটা, সিক্রেট বা Git ইতিহাস ক্লায়েন্টকে দেবেন না।
- আপনার নিজস্ব **বিল্ড মেশিনে** Python 3.9+, Git, অফিসিয়াল লাইসেন্সড ionCube Encoder এবং টার্গেট ভার্সনের PHP CLI-তে ionCube Loader চালু থাকতে হবে। বিল্ড মেশিনে সাইট হোস্ট করতে হবে না। ক্লায়েন্টের **ওয়েব PHP**-তেও সামঞ্জস্যপূর্ণ Loader লাগবে; তার CLI ও ওয়েব PHP একই নাও হতে পারে।
- বর্তমান ক্লিনআপ রিভিউ করে কমিট করুন। নিচের `REVIEWED_COMMIT`-এর জায়গায় সেই নতুন কমিটের hash লিখুন; প্রথম আপলোডের কমিট নয়। এই টুল শুধু ওই snapshot পড়ে, checkout বা সোর্স ফাইল overwrite করে না।

## কমান্ড

এনকোডিং ছাড়াই আগে তালিকা যাচাই করুন। এতে কোনো ZIP তৈরি হয় না:

```sh
python3 deploy/build_encoded_release.py --ref REVIEWED_COMMIT --check-only
```

**উদাহরণ:** ক্লায়েন্টের ওয়েব PHP `8.4` হলে, আপনার মেশিনে যোগ্য Encoder ও Loader সেট করার পর:

```sh
python3 deploy/build_encoded_release.py \
  --ref REVIEWED_COMMIT \
  --encoder /opt/ioncube/ioncube_encoder.sh --encoder-php 8.4 \
  --php /usr/bin/php8.4 --target-php 8.4 \
  --output dist/iconiconline-php84-encoded.zip
```

প্রকৃত ভার্সন ও ইনস্টলেশন পাথ বসাবেন। `--encoder-php` অফিসিয়াল `.sh` wrapper-এর জন্য; সরাসরি version-specific Encoder binary দিলে ওই option বাদ দিন। [ionCube-এর CLI ও compatibility গাইড](https://www.ioncube.com/sa/USER-GUIDE.pdf) মিলিয়ে নিন। PHP বা Loader না মিললে, Encoder কোনো PHP ফাইল কপি করে রেখে দিলে, অথবা এনকোড করা পরীক্ষার ফাইল না চললে বিল্ড থামবে। কোনো plain-source ZIP তৈরি হবে না।

**এখানে আসল এনকোডেড ZIP তৈরি হয়নি:** লাইসেন্সড Encoder পাওয়া যায়নি এবং ক্লায়েন্টের PHP/Loader নিশ্চিত করা হয়নি। বিল্ড সফল হলেও ক্লায়েন্টের প্রাইভেট স্টেজিংয়ে একই PHP ও Loader দিয়ে লগইন, CSS/ছবি, অ্যাডমিন রুট ও অনুমোদিত ওয়ার্কফ্লো পরীক্ষা করে তারপর ডেলিভারি দিন।
